# Установка без компьютера и Expo Go

После установки компьютер для работы дневника не нужен. Записи сохраняются на самом устройстве.

## Android: отдельное приложение APK

**Текущий статус: готового APK ещё нет.** Реальная release-сборка запущена, но загрузка обязательного `react-android-0.88.0-release.aar` перенаправляется с Maven Central на `repo.reactnative.dev`, который блокируется сетевой политикой этой облачной среды (HTTP 403). Нужно применить сохранённое разрешение этого домена и повторить сборку. JavaScript-экспорт не является APK.

Когда сборка завершится и подпись будет проверена, файл `fitness-android.apk` можно будет открыть на телефоне и разрешить установку этому браузеру или файловому менеджеру, если Android попросит. После установки «Дневник силы» откроется с главного экрана.

Это release-сборка со встроенным JavaScript/Hermes-пакетом. Ей не нужен Metro, компьютер, Expo Go или аккаунт Expo. Для локального релизного APK поддерживаются ARM64 и ARMv7; минимальная версия Android уточняется по манифесту готовой сборки. Подпись и наличие встроенного пакета проверяются скриптом только после успешной сборки.

Записи из Expo Go или браузера автоматически в APK не переносятся: это разные хранилища. Для обновления APK нужна подпись тем же ключом. Удаление приложения может удалить дневник, поэтому не удаляйте его перед обычным обновлением.

## iPhone: установка через Safari

Этот бесплатный вариант выбран вместо нативного приложения TestFlight.

1. Откройте опубликованный сайт проекта в **Safari** на iPhone.
2. Дождитесь надписи **«Готово к работе без интернета»**.
3. Нажмите **«Поделиться» → «На экран Домой» → «Добавить»**.
4. Откройте «Дневник силы» с новой иконки. Включите авиарежим и проверьте, что можно создать тренировку, записать подход и повторно открыть дневник.

После первой загрузки и сохранения файлов приложение работает офлайн. Браузерное хранилище может быть удалено при очистке данных сайта или системой; синхронизации и резервного копирования пока нет. Данные Expo Go и браузерной версии автоматически не объединяются.

Для обновления откройте приложение с интернетом, затем закройте все окна этой версии и откройте приложение снова. Обновление файлов интерфейса не очищает записи дневника.

Ожидаемый адрес сайта после включения GitHub Pages: **https://raxnud1k.github.io/Fitness/**. Ветка `gh-pages` уже загружена; доступность опубликованного сайта пока не подтверждена. Проверка GitHub API и сайта из этой среды блокируется сетевой политикой. Для этого сохранены разрешения `api.github.com` и `raxnud1k.github.io` в черновике настроек среды.

## Однократно включить публикацию

В репозитории `Raxnud1k/Fitness` откройте:

**Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: gh-pages → /(root) → Save**.

Дождитесь успешного развёртывания Pages. Затем откройте HTTPS-адрес сайта и проверьте, что он показывает приложение, а не ошибку 404. После этого его можно устанавливать на iPhone. Первое открытие требует интернета.

## Настоящая нативная версия iOS

Сборка IPA для установки через TestFlight или ad hoc требует Apple Developer Program и подписи. Она не заменяется простым скачиванием файла из репозитория. Профили `production` и `ios-device` подготовлены в `eas.json`, но без доступа к Apple Developer подписанная iOS-сборка не создаётся. Подробнее — в [IOS.md](IOS.md).

## Сборка для разработчика

Веб-версия:

```sh
npm ci
npm run build:web
npm run test:pwa
npm run publish:web
```

`build:web` создаёт `web-dist` для пути `/Fitness`: манифест установки, иконку и service worker с версионированием кэша. `publish:web` загружает только готовые публичные файлы в ветку `gh-pages`, сохраняя историю. Он не меняет рабочую ветку и отказывается заменять чужую ветку без маркера экспорта. GitHub Pages включается отдельно. Для другого пути задайте `FITNESS_WEB_BASE_PATH` при сборке и скорректируйте адрес размещения; тестовый сервер рассчитан на `/Fitness/`.

Android через EAS:

```sh
npx eas-cli@26.0.0 login
npm run build:apk
```

Для этого пути нужны аккаунт Expo и доступ к EAS. При первом запуске привяжите проект к своему аккаунту и сохраните его настоящий projectId в `app.json` (проект использует динамический конфиг `app.config.js`, который читает статические настройки). EAS управляет отдельным ключом подписи: для обновления уже установленного локального APK сначала импортируйте тот же ключ, а не создавайте новый.

Локальная release-сборка Android на Linux/macOS:

```sh
npm ci
npx expo prebuild --platform android --no-install
python3 scripts/build-android-local.py
```

Нужны полный **JDK 17**, Android SDK Platform 37.0, Build Tools 37.0.0/36.0.0, NDK 27.1.12297006 и CMake 3.22.1. Задайте `JAVA_HOME` на JDK 17 и `ANDROID_HOME` на SDK. При необходимости задайте `FITNESS_JAVA17_HOME`; число работников можно ограничить `FITNESS_BUILD_WORKERS`. Ключ подписи и его пароль создаются один раз вне репозитория: по умолчанию в `~/.fitness-signing`, либо в `FITNESS_SIGNING_DIR`. Их нужно хранить и резервировать безопасно; не публикуйте их в GitHub. Сборка проверяет подпись, наличие встроенного пакета и ARM64-библиотек, затем сохраняет APK и SHA256 в `artifacts/`.

`expo prebuild` создаёт игнорируемую папку `android` и может обновить команды `android`/`ios` в `package.json`; проверяйте изменения после запуска. Для независимого APK используйте release, а не debug.
